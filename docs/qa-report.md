# Arkad QA report — 2026-11-23

Scope: a code review of every area of the app (shared layer and database rules, portfolio and profile, feed/search/learn, communities chat, communities extras such as classroom, events and track records), plus a hands-on pass in the iOS simulator in light and dark mode on iPhone 16. Nothing in the code review was run; each finding was read in the code, and the simulator pass covered what a user sees. Database rules and 20 indexes were deployed to Firebase on 2026-11-23, before this QA.

How to read it: the app is in free mode (no paid features, no Cloud Functions). The phone computes stats and Firestore rules enforce what they can, on the Spark plan (50k reads and 20k writes per day). Each finding has an ID, a severity, what goes wrong, where (file:line, paths shortened), and a one-sentence fix. Status shows where each fix stands after this pass: "Fixed" is done in the app, "Fixed (rules, not deployed)" is written in `firestore.rules` but only takes effect once the rules are deployed, "Partly fixed" says what is left, "Needs you" is an owner action, and "Deferred" items are listed again under "Deferred / later". Duplicates across the reports are merged into one row.

What matters most, in plain words:

1. **The Finnhub API key is public.** It was committed to git and is still the live key. It also ships inside the app bundle. It must be rotated (see "Needs you").
2. **The Following tab crashes for anyone who follows more than 30 people.** Firestore rejects the query and the app dies.
3. **The first sign-up after a cold launch can crash.** The Firestore settings are changed after the database has already started, which the SDK treats as a fatal error.
4. **Track records and leaderboards can be faked.** Users can write their own stats, edit or delete their losing callout records, and close callouts with any result. The UI says "price checked", but the rules do not back that up.
5. **Private data is readable by any signed-in user.** Every user's email and starting capital, trades marked "Only you", and the content of private communities can all be read with a few lines of script.
6. **Anyone can write anything into anyone's notification inbox**, and every community chat message is copied into a public activity feed.
7. **Posts can fake likes, comments, dates and author names**, and profile edits overwrite follower counts and community lists with stale values.
8. **Spark quota is easy to burn.** Listeners stack up on every tab visit, chat reads one document per message for reactions, one Finnhub key serves every install with no throttle, and notifications are written one per member from the phone.

## What changed in this pass

- The Following tab no longer crashes for people who follow more than 30 accounts, and the first sign-up after a cold launch no longer crashes.
- Posting keeps the composer open and shows an error if the save fails, so text is not lost. Post, comment and like counts, feed paging, cashtags and deletes now behave correctly.
- Trades support shorts, price checks are tight (within 1% of a live quote, "Just now" only), and prices are never silently downgraded to self-reported when quotes are down. All quote calls share one throttled client.
- Callout and track-record results are checked against a fresh quote with a 0.25% tolerance, and deleting a losing callout can no longer erase the loss. Free-mode records are labelled as tracked by the app.
- Email and starting capital moved to an owner-only private profile, usernames are lowercase and claimed, and account deletion re-checks the password and cleans up comments and likes.
- Private communities now need an invite code, chat loads the newest 50 messages with "Load older", reactions live on the message, and non-members see "Join to chat".
- Events, reminders, classroom drafts and Markdown links are safer, and several screens got Dynamic Type, status-bar and avatar-initials fixes plus a privacy manifest.
- The rewritten `firestore.rules` enforce most security rows but are not deployed yet. Until they are, those rows are only fixed on paper.
- 108 unit tests were added; they compile but could not be run on this Mac (run them in Xcode with ⌘U). Writing them turned up two parsing bugs, now fixed.
- Still open: rotate the Finnhub key, App Check, partial position closes, running the tests, project settings cleanup, and a few smaller gaps listed as "Partly fixed".

## Needs you

These can only be done by the owner.

1. **Rotate the Finnhub API key now.** The current key is in git history (commits `c733697` and `fe7c8ce`, on GitHub with many remote branches) and also in the app bundle, so treat it as public.
   - Create a new key at finnhub.io.
   - Put it in `App/Secrets.plist` (untracked and ignored).
   - Revoke the old key at finnhub.io.
   - Optional: purge the old key from history (filter-repo plus a force-push of all branches). This does not replace rotating it.
2. **Approve deploying the new database rules** once the app update that matches them is ready. Tightening the rules before the update ships would break the current app, for example private-trade reads, notification writes and callout closes.
3. **Enable Firebase App Check later** (DeviceCheck / App Attest), after the app update is out, and restrict the Firebase API key to the app's bundle id in Google Cloud.
